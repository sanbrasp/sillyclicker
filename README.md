# SillyClicker

_(Eventual goal):_  
This aims to be a stupid little click-guessing game. Click boxes, find the hidden object, get points. Guess wrong three times and 
something ridiculous happens. Eventually this should render as a static image on my GitHub/GitLab profile.

---

## Why it was made

Personal practice project to get more reps in with concepts from my course in Backend Programming:  
encapsulation, separation of concerns, domain modeling, immutability, and a bit of algorithmic thinking.  
Also just wanted something dumb and fun to build.

---

## Why it's built this way

`GitHub` and `GitLab` strip scripts from profile READMEs and proxy/cache images, so there's no live backend to hit on click. 
Instead, every possible game state (every combination of "boxes clicked so far") gets pre-generated as a static SVG. 
Clicking a box just links to the next state's image. No server needed.

That constraint ended up being good practice for a few things: `GameLayout` and `GameState` are kept strictly separate (
permanent geography vs. changing progress), both protect their own invariants instead of exposing raw mutable data, 
and state changes always produce a new object rather than mutating in place. Enumerating every reachable state is also 
basically a small graph traversal problem, which lines up nicely with the sorting/algorithms work I'm doing this term.

## Project structure

```
SillyClicker/
├── Domain/
│   ├── GameLayout.cs   # Fixed box positions + which one is correct, for one round
│   └── GameState.cs    # Clicked-box bitmask + miss count; changes as the game is played
└── Models/
    └── BoxPosition.cs  # Plain immutable record: X, Y, Width, Height
```
